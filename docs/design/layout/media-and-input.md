# Detail media and input ownership

The detail page always starts with one 3D/minimap entry. If an author omits it, the adapter inserts it; additional minimap entries are ignored. `resolveSpatialElementData` preserves the authored collection for data consumers, while the page applies this presentation normalization. An empty collection therefore still shows the model entry on a detail page.

```ts
media: [
  { id: 'model', kind: 'minimap', label: '3D view' },
  { id: 'front', kind: 'image', label: 'Front view', src: '/front.webp', alt: 'Front of the enclosure' },
  { id: 'film', kind: 'video', label: 'Assembly', src: '/assembly.webm', poster: '/assembly.webp',
    captions: [{ src: '/assembly-en.vtt', language: 'en', label: 'English', default: true }] },
  { id: 'external', kind: 'youtube', label: 'Demonstration', videoId: 'M7lc1UVf-VE' }
]
```

Use unique media IDs. `video` and `youtube` accept an optional poster for the rail. Images require meaningful alternative text; caption tracks are native WebVTT tracks and should describe meaningful audio. The deprecated `drawing` kind had no actual source. Replace it with `image`; a source-less drawing displays an unavailable-media message rather than invented content.

## Display and lifecycle

All media uses the same layout-owned fit rectangle. Images and native videos retain their proportions with `object-fit: contain`. Neither the model nor its scene background remains behind a selected image/player. The stage keeps its loaded assets and camera but releases model input and device-orientation participation and stops submitting the hidden main scene. Selecting 3D restores it without another asset download.

Native videos use ordinary controls, `playsinline` and metadata preload. There is no autoplay. Removing a video pauses it and releases its source. A YouTube iframe is created only after selection, uses the privacy-enhanced host with autoplay disabled, and is removed on deselection. This is an external player with its own network and privacy behavior, not a locally hosted video. Invalid IDs and failed native media show a status message. Navigating away and back resets selection to 3D; media selection is not persisted in history or used as asset identity.

The rail may scroll horizontally or vertically. Revealing the selected item adjusts only the rail's own scroll position. It does not use document-level `scrollIntoView`. Panel projection is invalidated once per rail scroll frame so its visible controls remain aligned.

## Input boundaries

| Context | Free area behavior | Controls |
| --- | --- | --- |
| Flow detail, 3D selected | A contact on the model rotates; outside it scrolls the document | Native UI keeps its input |
| 3XL split, 3D selected | The free area left of the pane controls the model | Rail, menu, pane and player UI take priority |
| 3XL zoom with hidden pane | The entire free viewport can control the model | Visible 3D controls take priority |
| Image/video selected | Free areas scroll the document | Native player controls retain playback input |
| Inside YouTube iframe | The embedded document owns the interaction | Host cannot reliably redirect cross-origin wheel/touch events |

The owner is chosen at gesture start and remains fixed until release. Crossing the pane boundary mid-drag does not switch the gesture from rotation to scroll. There is no transparent event-catching layer over a player.

## Verification and limits

`playwright.detail-media.config.ts` runs the public `/demo/layout-media` fixture in production: SSR/no-JavaScript starts with the model poster; native image/video selection works without WebGPU; video playback stops on removal; rail overflow, failed media and history reset are checked. The WebGPU case checks that the main-model render counter stops while an image is selected and resumes on return, and that the 3XL free area scrolls the document for image media.

The embed test intercepts the remote iframe with a local player-control fixture. It verifies URL, explicit creation, teardown and event boundary, not YouTube service availability or remote playback. Pure interaction tests cover gesture ownership and boundary crossing. Physical Android, Surface and iOS input/permission checks remain part of the final device review; desktop automation is not evidence of those hardware tests.

The small demo video is generated by `scripts/generate-demo-video.mjs`; the script verifies native playback before writing the fixture. It is silent and has a descriptive caption track.
