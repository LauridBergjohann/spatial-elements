# Pre-route dock geometry

`createStagedDockGeometry` is a CPU descriptor for a known, fully docked XS–2XL detail destination. It reads the canonical layout resolver, actual prepared Low mesh bounds, the shared detail/LOD center, the canonical model-root matrix, stage camera settings and merged minimap options. It performs no DOM reads, renderer calls, resource uploads or pipeline compilation. Authored model rotations and mesh exclusions must already be represented by the prepared asset; the helper does not apply them a second time.

The Low bounds must be the bounds of the included Low meshes in the prepared canonical frame. A LOD pair's declarative common bounds can differ from those actual bounds and cannot be substituted. The shared center remains the detail/LOD pivot even when the Low bounds have a different center. The descriptor uses the mounted minimap's bounding-sphere fit, inset, model scale, optional docked angle overrides, depth range and off-axis screen camera. Stable layout metrics place the dock; the actual renderer viewport determines projection. An explicit three-decimal dock-scale normalization matches the current mounted presentation attribute.

Arrival is a neutral pose: zero sensor rotation, no pointer hover, no panel tilt, camera focus zero, dock progress one. The descriptor itself does not control sensor lifetime. `StageExperience.beginStagedDetailMotion` obtains a shared sensor hold only after successful source capture. The hold resets the sensor baseline, pauses samples across route-owner replacement and remains active through destination binding. `finishCatalogGeometry` (also cancellation cleanup) or Stage disposal releases it exactly once; sampling then recalibrates to the new grip and uses the existing gradual scroll recovery. Independent source interaction state must not leak into this endpoint. Hover multipliers and theme decoration do not change the resting fit.

An arbitrary URL hash does not prove that the destination is docked. Eligibility and validation belong to the navigation coordinator and an explicit destination contract. A real 3XL split layout returns `undefined`, because its destination is the fixed main stage plus pane header. A short 3XL viewport that resolves to the 2XL flow fallback has a normal dock endpoint. Unknown or unavailable asset geometry also declines rather than guessing.

`stagedDockGeometry.spec.ts` checks numeric responsive endpoints, safe areas, classic scrollbar gutters, differing layout/render heights, authored Low geometry, a distinct common pivot, partial dock angle overrides, scale limits, WebGPU/WebGL projection conventions and matrix/projected-corner parity against the actual `MinimapController`. This is CPU parity, not a claim that a production early dock transition or its GPU readiness gate has passed.

## Live Dock content handoff

The source surface and text move as separate real DOM actors while their whole presentation root is inert. A reversible clipping lease opens source ancestors without changing their local box or reserved scrollbar space. A source with a nonzero internal scroll offset or genuinely clipped overflow uses the ordinary transition, because opening it would otherwise reset its scroll position or expose hidden snippet content. The main menu exits for a Dock destination; continuity remains a Hero-only decision.

During content reveal, the original source actors remain held and fade out while the destination header surface and text fade in. Only after reveal reaches one does the `committing` phase transfer the original Carousel summary instance into the destination summary slot. It awaits Svelte updates, synchronous panel measurement and rebind before releasing ownership. Cancellation aborts this final phase, and late completion cannot finish or clean up the same transition twice. The Card renderer still has a distinct destination renderer and is released after reveal instead of being adopted as a summary.
